Deploy on Railway, Render, or Fly.io with community-maintained templates. Each runs the published image and wires a health check.

<Callout type="warn" title="Starting-point templates, not verified pipelines">
These are starting-point templates, not verified CI pipelines. They have not been boot-tested end-to-end against a live ClickHouse instance in automated CI. Review env placeholders, substitute real values, and verify before production.
</Callout>

```mermaid
flowchart LR
  T[Template] --> P[Railway / Render / Fly]
  P --> Img[ghcr.io image]
  Img --> HZ["/api/healthz"]
  Img --> CH[(ClickHouse)]
```

## Prerequisites

All three templates use `ghcr.io/chmonitor/chmonitor:latest`, expose port 3000, and health-check `/api/healthz`. You must supply:

| Variable | Description |
|---|---|
| `CLICKHOUSE_HOST` | ClickHouse HTTP URL, e.g. `http://your-host:8123` |
| `CLICKHOUSE_USER` | ClickHouse username |
| `CLICKHOUSE_PASSWORD` | ClickHouse password (platform secret store) |

Templates live in [`deploy/templates/`](https://github.com/chmonitor/chmonitor/tree/main/deploy/templates).

## Setup

<Tabs items={["Railway", "Render", "Fly.io"]}>
<Tab value="Railway">

Template: [`deploy/templates/railway.json`](https://github.com/chmonitor/chmonitor/blob/main/deploy/templates/railway.json)

<Steps>
<Step>
### Create a new project

In the Railway dashboard, choose **New Project → Deploy from image** and set the image to `ghcr.io/chmonitor/chmonitor:latest`.
</Step>

<Step>
### Set environment variables

Go to **Variables** and add the three env vars above. Use Railway's secret management for `CLICKHOUSE_PASSWORD`.
</Step>

<Step>
### Open your app

Railway auto-assigns a public URL. Health check path: `/api/healthz`.
</Step>
</Steps>

Alternatively, copy `deploy/templates/railway.json` into the repo root as `railway.json`.

```json
{
  "build": {
    "builder": "IMAGE",
    "image": "ghcr.io/chmonitor/chmonitor:latest"
  },
  "deploy": {
    "healthcheckPath": "/api/healthz"
  }
}
```
</Tab>

<Tab value="Render">

Template: [`deploy/templates/render.yaml`](https://github.com/chmonitor/chmonitor/blob/main/deploy/templates/render.yaml)

<Steps>
<Step>
### Fork or copy the template

Copy `deploy/templates/render.yaml` as `render.yaml` in the repository root.
</Step>

<Step>
### Create a Blueprint

In Render: **New → Blueprint** and point it at your repository.
</Step>

<Step>
### Set the password as a secret

Render pulls `ghcr.io/chmonitor/chmonitor:latest`. Set `CLICKHOUSE_PASSWORD` as a **Secret** (do not leave it in `render.yaml`).
</Step>
</Steps>

```yaml
services:
  - type: web
    name: chmonitor
    image: ghcr.io/chmonitor/chmonitor:latest
    healthCheckPath: /api/healthz
    envVars:
      - key: CLICKHOUSE_HOST
        value: http://YOUR_CLICKHOUSE_HOST:8123
      - key: CLICKHOUSE_USER
        value: YOUR_CLICKHOUSE_USER
      - key: CLICKHOUSE_PASSWORD
        value: YOUR_CLICKHOUSE_PASSWORD   # use Render secret instead
```
</Tab>

<Tab value="Fly.io">

Template: [`deploy/templates/fly.toml`](https://github.com/chmonitor/chmonitor/blob/main/deploy/templates/fly.toml)

<Steps>
<Step>
### Install Fly CLI and login

```bash
# Install: https://fly.io/docs/hands-on/install-flyctl/
fly auth login
```
</Step>

<Step>
### Copy and edit the template

Copy `deploy/templates/fly.toml`. Edit `app`, `primary_region`, and `CLICKHOUSE_HOST` / `CLICKHOUSE_USER`.
</Step>

<Step>
### Store the password as a secret

```bash
fly secrets set CLICKHOUSE_PASSWORD=your-password
```
</Step>

<Step>
### Deploy

```bash
fly launch --no-deploy   # imports fly.toml
fly deploy
```
</Step>
</Steps>

Health check polls `/api/healthz` every 10 seconds with a 20-second startup grace.

</Tab>
</Tabs>

## Verify

- Open `https://your-app-url` — overview should load.
- Empty charts → ClickHouse user needs `SELECT` on `system.*`.
- Health check fails → `CLICKHOUSE_HOST` must be reachable **from the container** (private hostname, not `localhost`).
