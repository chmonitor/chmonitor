# ClickHouse 26.10 System Table Changes

Source: `system.columns` diff between the official `clickhouse-common-static`
binaries 26.9.25.15 and 26.10.2.103 (2026-10-25), on a server with the log
tables enabled. Only tables that chmonitor query configs read are listed.

## New Columns

### system.query_log

| Column | Description |
|--------|-------------|
| `used_number_of_joins` | Number of joins the query executed |
| `used_join_algorithms` | Join algorithms the query used |
| `used_join_kinds` | Join kinds the query used |
| `used_join_strictness` | Join strictness values the query used |
| `spilled_to_disk` | Operators that spilled to disk (`join`, `distinct`, ...) |

### Other tables

| Table | Columns |
|-------|---------|
| `system.processes` | `spillable_memory_bytes` |
| `system.clusters` | `replica_group` |
| `system.dictionaries` | `is_lazy` |
| `system.errors`, `system.error_log` | `last_error_lines`, `last_error_symbols` |
| `system.scheduler` | `reclaimable`, `reclaiming`, `soft_limit`, `spills` |
| `system.quota_limits` | `max_written_rows` |
| `system.quota_usage`, `system.quotas_usage` | `written_rows`, `max_written_rows` |
| `system.processors_profile_log` | `exception`, `exception_code` |
| `system.blob_storage_log` | `source_bucket`, `source_remote_path` |

## Removed Columns

Ten `ProfileEvent_*` columns of `system.query_metric_log`, among them
`ProfileEvent_CachedReadBufferPredownloadedBytes`,
`ProfileEvent_ParallelReplicasDeniedRequests` and
`ProfileEvent_WasmMemoryAllocated`. No chmonitor query reads any of them.

## Retyped Columns

All retypes extend an enum or a tuple, and no config filters on the new values:

- `processes.interface` and the `interface` column of `query_log`,
  `query_thread_log` and `session_log`: the enum gains `IcebergRESTCatalog`.
- `blob_storage_log.event_type`: gains `Copy`.
- `zookeeper_log.op_num`: gains `ListWithOptions`.
- `grants.access_type`: gains new access types.
- `parts.creation_tid`, `parts.removal_tid`, `query_log.transaction_id`: the
  tuple gains a fourth `Int64` element.

## Notes

- Every registered query config and chart builder plans (`EXPLAIN PLAN`) and
  runs on 26.10.2.103 (`bun scripts/audit-query-configs.ts`). No `since:`
  variant was needed.
- 26.10 accepts `enable_analyzer = 0` and `allow_experimental_analyzer = 0`
  but ignores them: `getSetting('enable_analyzer')` still returns `true`. 26.9
  rejects `allow_experimental_analyzer = 0` with `SETTING_CONSTRAINT_VIOLATION`,
  which is why the app drops analyzer-off settings on 26.9+ (#3984).
- chmonitor does not select any of the new columns yet.

## LLM Context

When generating queries for ClickHouse 26.10+:

- `system.query_log` has `used_number_of_joins`, `used_join_algorithms`,
  `used_join_kinds`, `used_join_strictness` and `spilled_to_disk`
- `system.processes` has `spillable_memory_bytes`
- `system.dictionaries` has `is_lazy`; `system.clusters` has `replica_group`
- The old analyzer is gone: do not rely on `enable_analyzer = 0`
