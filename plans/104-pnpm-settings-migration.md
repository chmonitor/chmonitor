## Why this matters

pnpm ≥10.14 moved `overrides` / `onlyBuiltDependencies` from `package.json`'s
`pnpm` field into `pnpm-workspace.yaml`. pnpm 10.18 (this repo's pin) **no
longer reads the old location**: every install/audit prints

```
[WARN] The "pnpm" field in package.json is no longer read by pnpm. The following keys were ignored: "pnpm.onlyBuiltDependencies", "pnpm.overrides".
```

Consequences right now:

1. The next fresh install on a machine with a current pnpm resolves **without
   any of the ~31 root security floors** (axios, ws, zod, dompurify, qs,
   lodash, minimatch, undici…). Lockfiles still carry the old resolution, so
   nothing breaks until the first lockfile regen — then the pins silently
   vanish in a PR no reviewer will notice.
2. `onlyBuiltDependencies` being ignored means cypress/esbuild/sharp/workerd
   postinstall scripts may be blocked on fresh installs (pnpm 10 default-deny),
   which can break CI installs outright.
3. Two different machines can resolve two different trees → install-time drift
   between CI and local.

Verified during the audit: `cd apps/dashboard && pnpm audit --prod` currently
reports 8 high advisories; the override block that was supposed to hold some of
these back is demonstrably not applied to new resolutions.

## Steps

1. For each of the 7 manifests listed above, cut the entire `"pnpm": {...}`
   object from `package.json` and append to the sibling `pnpm-workspace.yaml`
   as top-level keys (YAML):

   ```yaml
   onlyBuiltDependencies:
     - cypress
     - esbuild
     - sharp
     - workerd
   overrides:
     axios: ^1.16.0
     # … byte-for-byte the same keys/values as the JSON block you removed
   ```

   Dashboard's yaml keeps its existing comment header and `packages:` list.
   Note: `onlyBuiltDependencies` belongs ONLY in workspaces that had it in
   package.json (root has it; check each app individually).
2. Regenerate all lockfiles: at repo root `pnpm install` then
   `cd apps/dashboard && pnpm install` (and any other app whose manifest you
   touched — docs, landing, blog, cloud-hooks, bug-handler each have their own
   lockfile; run their installs too).

   **Verify**: `grep -c "overrides:" pnpm-lock.yaml` → count > 0 AND the
   warning line `no longer read` is GONE from install output.
3. Full verification battery:

   ```bash
   pnpm run type-check    # exit 0
   cd apps/dashboard && bun test src/lib --isolate   # spot suite passes
   ```
